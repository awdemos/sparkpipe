# GLM52 SM121 B12x compiled backend

This module is the production C/CUDA runtime shell for the FlashInfer B12x fused MoE primitive. It does not contain a slow replacement kernel. It exports:

```text
SparkFlashInferB12xCompiledMoeCreate
SparkFlashInferB12xCompiledMoeLaunch
SparkFlashInferB12xCompiledMoeDestroy
```

It intentionally depends on the one-time generated B12x kernel table and exported TVM-FFI objects:

```text
SparkGlm52Sm121B12xGeneratedManifestInstance
SparkGlm52Sm121B12xGeneratedLaunch
```

Those symbols and objects are generated by `tools/glm52_b12x_aot_compile.py` on the SM121 machine and linked into the final decode-stage package. If they are absent, the package link fails.

Runtime does not import Python, Torch, FlashInfer, or CuTe DSL. It only calls the generated TVM-FFI object symbols through the generated C/CUDA launch table.

## Build modes: FP8-only vs NVFP4

Production runs FP8 MoE (`LAYER_ROUTED_FP8_TOPK`) and never dispatches the
NVFP4 B12x path (`LAYER_ROUTED_NVFP4_TOPK`). The two required generated
symbols above are only reachable at runtime through the NVFP4 path, but the
decode-stage object references them unconditionally, so the link needs them
present even for an FP8-only build.

`GLM52_MOE_BACKEND` selects how they are provided:

- `GLM52_MOE_BACKEND=fp8` (default): the generated kernel table archive is
  built from the checked-in stub
  `source/spark_glm52_sm121_b12x_generated_kernel_table_unavailable.c`. Its
  manifest has `bucket_count=0`/`buckets=0`, which the backend validator
  rejects with `SPARK_STATUS_ABI_MISMATCH`, and `GeneratedLaunch` returns
  `SPARK_STATUS_MODULE_NOT_VALIDATED`. So an FP8-only build links with no AOT
  step and no external environment, and any accidental NVFP4 dispatch fails
  loud rather than silently. This is the production build.

- `GLM52_MOE_BACKEND=nvfp4`: the generated kernel table archive is built from
  the real AOT output of `tools/glm52_b12x_aot_compile.py`
  (`runtime_link_args.txt`, generated `.cu`, exported TVM-FFI objects). This
  requires the SM121 AOT environment and is only for enabling the NVFP4 path.

The stub and the AOT output produce the same archive name, so nothing
downstream of the archive changes between modes.
